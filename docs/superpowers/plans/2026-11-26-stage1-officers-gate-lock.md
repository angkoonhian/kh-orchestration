# kh-orchestration stage 1: officers, commit gate, approval lock — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Claude Code plugin that, once installed in a repository beside kh-harness 0.3.0 or later, refuses any commit or merge commit whose exact tree has not passed the repository's officers, and lets the files that decide what "passing" means change only with the owner's approval.

**Architecture:** The plugin installs a small set of scripts into `.claude/kh-orchestration/scripts/` and copies them into the repository's shared git directory, where two git hooks run the gate. A verdict is a JSON record keyed by tree and base, written by `run` after every officer has run. One hand-written, self-contained hook extension, registered through kh-harness contract 1, blocks the ways around the gate from inside a session. Nothing is bundled and nothing is long-running.

**Tech Stack:** Node 22 or later, ESM, `node:` built-ins only, `node --test`. git 2.24 or later (`pre-merge-commit`). Python 3 only for the V11 example officer.

**Spec:** `docs/superpowers/specs/2026-11-25-kh-orchestration-v1-design.md` (sections "Stage 1" and "Corrections after stage 0 was built"), and kh-harness's `docs/CONTRACT.md` at kit 0.3.0, which is the authority for everything kh-harness provides. The sibling checkout is expected at `../kh-harness`; tests read its path from `KH_HARNESS_DIR`, defaulting to that.

## Global Constraints

- Zero runtime dependencies. Node 22 or later. ESM. `node:` built-ins only, in every file.
- Every message a command or hook prints is fixed text with values substituted; no stack trace ever reaches a person or a model. A refusal names the exact command to run next.
- A gate never passes because it crashed, timed out or was skipped: every uncaught failure in the gate, the runner or the extension ends in a refusal with fixed text. The single exception is the owner's off switch.
- `apply` is a dry run unless `--yes`; every file it writes and every patch it makes is recorded in `.claude/kh-orchestration.manifest.json`; it never overwrites a file it did not write; `uninstall` leaves the repository as it was.
- No second copy of anything kh-harness owns: one rules registry (`docs/harness/RULES.md`), kh-harness's session log, kh-harness's hook process. kh-orchestration registers no `PreToolUse` hook of its own.
- kh-harness is relied on only through contract 1, verified with `checkContract1` and `probeContract1` returning no problems and no warnings. Never import an installed kh-harness script before its hash has been checked.
- The hook extension is one file that imports `node:` built-ins only, exports a synchronous `preToolUse(payload)`, starts no process and awaits nothing.
- Commands run without a shell (`spawnSync(file, argv)`), with `GIT_OPTIONAL_LOCKS=0` for read-only git calls.
- Files written under the shared git directory are written by temporary file and rename.
- Tests build real git repositories in temporary directories. No test touches `~/projects/vyugate` or any repository outside its own temporary directory.
- Sample credentials in tests are built at runtime, never written as literals.
- Commits follow kh-harness's style: `type(scope): a sentence saying what is now true`.

## Decisions made in this plan

The design leaves these open; each is settled here so every task agrees.

1. **Layout of the plugin repository.**
   - `.claude-plugin/plugin.json`, `hooks/hooks.json` (one `SessionStart` hook), `skills/orchestrate/SKILL.md`.
   - `scripts/detect.mjs`, `scripts/apply.mjs`, `scripts/uninstall.mjs`, `scripts/session-brief.mjs`: run from the plugin.
   - `scripts/lib/`: installer code and its tests.
   - `assets/scripts/`: the files installed into a target, each with its test beside it in `scripts/lib/` (tests are not installed).
   - `examples/vyugate/`: the V8 and V11 officers and their tests.
2. **Installed files** in `.claude/kh-orchestration/scripts/`: `ko.mjs` (the command line), `gate.mjs`, `extension.mjs`, `ko-git.mjs`, `ko-state.mjs`, `ko-registry.mjs`, `ko-digest.mjs`, `ko-officers.mjs`, `ko-verdict.mjs`, `ko-contract.mjs`, `verify-contract-1.mjs`. Each begins with a stamp line `// Generated by kh-orchestration <version>. Do not edit.`
3. **No bundler.** `extension.mjs` is written by hand as one self-contained file. Pure helpers that other files also need (path normalising, the protected-path test, splitting a shell command into words) live in `extension.mjs` and are imported from it. A test asserts it has no import other than `node:` specifiers.
4. **`verify-contract-1.mjs` is copied verbatim** from kh-harness's `scripts/lib/fixtures/contract-1/verify-contract-1.mjs`, below the stamp line. A test compares it with the sibling checkout's file and fails when they differ.
5. **Shared state** lives in `<git-common-dir>/kh-orchestration/`:
   - `bin/`: a copy of the installed scripts, which the git hooks run;
   - `verdicts/<tree>-<base>.json`; `approvals.json` (`{ digests: [{ digest, approvedAt, branch }] }`);
   - `waivers.json`, `exemptions.json`, `proposals.json` (worktree paths open for proposals), `off` (a file whose presence is the switch), `journal.jsonl`.
6. **`officers.json`** is `{ "schema": 1, "baseBranch": "main", "officers": [ … ] }`. The base branch is part of the protected file, so changing it needs approval.
7. **Base.** `base` is `git merge-base HEAD <baseBranch>`; on the base branch itself, or when the base branch does not exist, it is `HEAD`; on an unborn `HEAD` it is the literal `none` and every tracked file counts as changed. A detached `HEAD` is treated like a branch other than the base branch.
8. **Changed files** are `git diff --name-only -z --no-renames <base> <tree>` (both sides of a rename count).
9. **Globs** are matched by one small function in `ko-officers.mjs`: `**` crosses directories, `*` and `?` do not, everything else is literal, paths use `/`. No brace or bracket forms.
10. **Officers' environment.** Each officer runs with the working directory at the repository root and with `KO_OPTIONS` (its `options` as JSON), `KO_BASE`, `KO_TREE` and `KO_CHANGED_FILE` (the path of a file listing changed paths, NUL-separated). Its timeout is `timeoutSeconds`, default 600, at most 3,600; a timeout is a failure named as a timeout. Output kept per officer: the first 4,000 characters of standard output and standard error joined.
11. **The digest** is the SHA-256 of a canonical text built from a tree object, never from the working directory: one line `path\0sha256\n` for each protected path in the tree, sorted by path, where the hash is of the blob's bytes; `docs/harness/RULES.md` contributes the hash of its canonical form instead (decision 12). A protected path absent from the tree contributes nothing. Officer scripts are the repository-relative paths found in each officer's `argv` that exist in the tree.
12. **Canonical form of `RULES.md`.** Parse by the contract's registry rules. The text before the first rule is kept whole. A rule without `approval: agent` contributes its whole block, byte for byte. A rule with `approval: agent` contributes its ID and its `approval`, `enforced-by` and `pointer` lines only. Anything the parser reports as a problem makes the digest unapprovable: `run` and the gate refuse and name the line.
13. **Who is the owner.** Owner-only commands (`approve`, `propose`, `waive`, `exempt`, `off`, `on`) refuse when the environment has `CLAUDECODE` or `CLAUDE_CODE_SESSION_ID` set, and the extension blocks a session from running them. Observed 2026-11-26 on Claude Code 2.1.330: a session's shell carries `CLAUDECODE=1` and `CLAUDE_CODE_SESSION_ID`. This guards against a skipped step, not against an agent set on cheating; the design's "Known limits" says so.
14. **The session id** for `recordExternalEvent` is `CLAUDE_CODE_SESSION_ID`. Without it, or when `files` in the contract file does not list `harness-log.mjs` and `harness-seal.mjs`, the run journal is the only record.
15. **What the extension blocks.**
    - `Edit`, `Write`, `MultiEdit` and `NotebookEdit` whose target, made repository-relative, is a protected path other than `docs/harness/RULES.md`, unless this worktree is open for proposals.
    - The same tools targeting anything under the git directory's `hooks/` or `kh-orchestration/`, always.
    - `Bash` whose command, split into words with quotes removed, has: `git` with `commit` or `merge` and `--no-verify`, or `-n` on `commit` (also inside a bundled short-option group such as `-an`); `git` with `-c` or `--config-env` naming `core.hooksPath`; `git config` naming `core.hooksPath`; `git commit-tree`; an owner-only `ko.mjs` command; or any word containing `/kh-orchestration/` under a `.git` path, or `.git/hooks`.
    - A `Bash` command that cannot be split (unbalanced quotes) and contains `git` is blocked.
    - It does not try to detect a protected file changed through `Bash`. The digest at commit and the gate's contract check are what catch that, as the design says.
16. **Finding the shared state without starting a process.** The extension reads `.git`: a directory is the git directory; a file `gitdir: <path>` points at the worktree's git directory, whose `commondir` file names the shared one. Anything else: block with fixed text, since the state cannot be read.
17. **The gate's order of checks:** off switch → the branch is exempt → the install is present in the tree → contract 1 verified in the working directory (`checkContract1`, `probeContract1`) → `RULES.md` parses → the digest is approved → a passing verdict exists for this tree and base. The first failing check is the one reported, with its command.
18. **Git hooks** are written to `<git-common-dir>/hooks/pre-commit` and `pre-merge-commit`, each a POSIX `sh` script of three lines that runs `node "$(git rev-parse --git-common-dir)/kh-orchestration/bin/gate.mjs" <hook-name>` and exits with its status. When `core.hooksPath` is set, or either hook file exists and is not ours, `apply` writes neither, reports the conflict and prints the line to add.
19. **`approve`** shows `git diff` of the protected paths between the last approved tree on this branch and the index, asks for the word `approve` on standard input, records the digest, closes any open proposal for this worktree and refreshes `bin/` from the approved tree's scripts.
20. **`verify-branch`** re-runs the officers by default on a tidy tree and then applies the gate's checks to `HEAD`; `--no-run` only reads the existing verdict. Its report lists exemptions, waivers and every rule changed by an agent since the base.
21. **vyugate itself is not touched by any task.** Tasks build and test the two officers against fixture repositories. Installing into vyugate is the owner's step, described in Task 12.

## Review Focus

1. **A crash anywhere in the gate.** A missing `bin/` file, an unreadable verdict, a corrupt `approvals.json`, `node` absent from `PATH` inside the hook: each must refuse the commit with fixed text, never allow it. (Tasks 6, 9)
2. **Linked worktrees.** vyugate work happens in Orca worktrees. Verdicts, approvals and hooks must be found from a linked worktree, and a proposal opened in one worktree must not open another. (Tasks 2, 7, 8)
3. **The first commit and the base branch.** An unborn `HEAD`, a repository with no `main`, committing on the base branch, and a `--no-ff` merge into it. (Tasks 2, 6)
4. **A second plugin's entry in `extensions.json`.** Install and uninstall must leave it exactly as it was, in place. (Task 9)
5. **A command the word-splitter reads wrongly.** `git commit -m "fix -n flag"` must not be blocked; `git commit -an`, `git -c core.hooksPath=/x commit` and `env X=1 git commit --no-verify` must be. (Task 8)
